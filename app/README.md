# StudyBuddy: Electromagnetics I vertical slice

An authored, deterministic, interactive mastery workspace for UTech ELE3001 (Electromagnetics I).
**AI at build time, deterministic learning at runtime:** zero LLM calls while a student uses it.

- Spec: `../docs/superpowers/specs/2026-09-25-em1-vertical-slice-design.md`
- Plans: `../docs/superpowers/plans/`
- Vision: `../Interactive Study Workspace.md`

## Run it

```bash
pnpm install
pnpm test            # 108 unit tests: engine, physics, course content (every numeric answer physics-verified)
pnpm typecheck
pnpm --dir apps/web dev          # http://localhost:3100
pnpm --dir apps/web e2e          # Playwright: journey, return experience, a11y (axe), 4× throttled CPU
```

## Layout

| Path | What it is |
|---|---|
| `packages/physics` | Field, flux and surface-integral numerics (Gauss–Legendre quadrature). Tested against analytic results. |
| `packages/engine` | Course grammar (Zod), answer checking with units and error classes, mastery (5 dimensions → 6 states), spaced review, rules reducer, diagnostic router, structural lint. No DOM, no React. |
| `packages/course-em1` | The course: 8 concepts plus 6 locked ones, 5 misconception detours, diagnostic, past papers, formula sheet, lab goal checks. `PUBLISH_REPORT.md` is regenerated by `pnpm test`. |
| `apps/web` | Next.js 16 workspace: shell, lesson player, block renderers, 3D Gauss lab (React Three Fiber) with a 2D fallback, and the journey screens. |
| `tools/extract.py` | Pulls per-page text out of `../Resources/Electromagnetics` into `content-src/extracted/` (gitignored). |

## What's in the prototype (the spec's 15 pieces)

1. Landing: continue card, route, finals countdown, reviews due.
2. Readiness diagnostic: 6 topics, core question plus a probe after a miss, builds a refresher route.
3. Concept map (xyflow): mastery rings, locked nodes.
4. Refresher: surface elements and flux integrals, with a tilting-patch 3D scene.
5. Flux → Gauss lesson: Faraday hook, predictions, the lab, equation build, "questions you might ask" branches, checkpoint.
6. Progressive equation build: each term lights up its part in the 3D lab.
7. 3D lab: draggable charges, D arrows, sphere / cube / lumpy blob surfaces, resize, normals, per-patch flux shading, live Ψ and Q_enc.
8. Commit-before-reveal predictions.
9. Five misconception detours, triggered by rules (same tag twice); the learner returns to the exact block.
10. Worked problems (tutorial Q.06, Q.08, Q.09) with three hints each and the worked step revealed after three misses.
11. Mastery challenge: a first-try pass offers skip-ahead and credits "application".
12. Past papers: Finals 2024-25 Q2(a) and 2023-24 Q2(b), broken down by concept, with readiness.
13. Notebook: equations, reflections, and frozen lab states that restore on click.
14. Return experience: a summary after 2+ days away plus 2 retrieval questions. Settings has a developer "days ahead" control for testing it.
15. Mastery dashboard: concepts × dimensions, recurring sticking points, review queue, exam coverage.

Also: Explore mode (`/lab`), and settings for theme, motion, density, simulation quality and equation detail.

## Workspace pass (September 2026)

The browser app now presents StudyBuddy as the workspace and ELE3001 as its first course. The landing screen contains a live 3D experiment; lessons have a nearby desk for working paper, lab, problems, and notebook. The open lab supports charge magnitude, shape and size changes, reset, and three experiment prompts. Working paper uses `js-draw` for pen/stylus/mouse strokes, keeps an editable draft in IndexedDB, and saves SVG plus typed reasoning to the notebook. The reference clones and their licenses are listed in `../references/README.md`.

This is a structural and interaction pass, not a finished multi-course product. The course content is still EMag only; other engines from the repo shortlist have not been bundled. Native mobile and desktop apps are later targets; the browser workspace is the current product.

## Pedagogy audit against the vision notes

Implemented:
- prediction before reveal; self-explanation ("I chose it because…")
- retrieval practice and spaced review (intervals tighten near the exam)
- progressive reveal; multiple representations linked by colour (prose ↔ equation ↔ 3D)
- feedback, not judgement: amber ↺ with the reason and a named error class; red only for system faults
- colour is never the only signal; varied rhythm; learning moods
- respect for strong students (prove mastery, skip ahead); no XP, streaks or confetti
- cognitive-environment settings; re-entry after time away
- provenance on every block (ⓘ, plus the Sources drawer); "Level 5" advanced branch

Known gaps (deliberately deferred):
- Equations aren't clickable ("What does ∇· mean?" menus).
- The lab can't change charge magnitude or ε_r, and has no equipotentials yet.
- Causal animation chains (600–900 ms) exist only as term pulses.
- No time-based session modes ("30 minutes", "exam revision").
- No authoring UI, no course versioning, no analytics beyond local history.
- `identify` blocks fall back to multiple choice.
- The visual identity is a first workspace pass. Theme values live in `apps/web/app/tokens.css` and can change without editing lessons.

## Content and licensing

Every block has a `source` and a `licence`. Material quoted from UTech slides, past papers and textbooks is `restricted` (fine for private use by classmates). Before a public release, list the restricted blocks and replace them with original material.

## Next: accounts

The Portfolio site (`C:\Portfolio-main\frontend\functions`) already has member auth on Cloudflare Pages Functions:
- PBKDF2 password hashes
- HS256 JWT in a session cookie
- Google OAuth
- users stored in KV (`USERS`)
- `GET /api/auth/me` returns the current user

Every StudyBuddy route is statically generated, so the simplest path is:
1. Set `output: "export"` in `apps/web/next.config.ts` and deploy `out/` to the same Cloudflare Pages project (or a sub-path), so the session cookie is shared.
2. Add `/api/progress` Pages Functions (GET/PUT, KV keyed by user email) and sync `LearnerState` there when signed in. Browser storage stays the offline cache.
